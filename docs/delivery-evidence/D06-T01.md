# D06-T01 — Make Hub queue reads and selected-source requests truthful

**Owner task / date:** current implementation coordinator, 2026-09-08

**Base / implementation revision:** `0046849` / `c18640a`

**State:** review; local reader and request-fence behavior passed, while responsive browser, independent QA, Realtime freshness and deployment acceptance remain unverified.

The canonical Intake reader now returns an explicit discriminated result instead of collapsing both an empty queue and a service/read failure into `[]`. A successful empty result clears the last Hub snapshot and closes a selection that no longer exists. A genuine error preserves the last successful rows and displays an honest warning. Initial server rendering, manual refresh, post-assignment reconciliation, the legacy Inbox compatibility caller, and the navigation count all consume the same result contract.

The live Document Hub source opener now fences every signed-URL response with both the selected Intake subject and a monotonically increasing request generation. Selecting another row, closing details, or closing the source invalidates the outstanding request immediately and clears its pending presentation. A late success or error for row A can therefore neither render nor overwrite source state after row B is selected. Queue refreshes still derive the selected row from the latest authoritative snapshot, so updated metadata is not copied into a second client-owned record.

Developer evidence passed on Node 24 / Next 16.2.9: six focused queue/state tests cover canonical Intake actions, successful empty replacement, genuine-error preservation, and the wired subject/generation fence; TypeScript, whitespace validation, scoped ESLint for the D06 Hub/page/action/helper files, and the webpack production build pass. The legacy `InboxClientView` compatibility caller compiles but retains unrelated B02 lint debt, so no whole-file lint pass is claimed. The local protected route redirected to login and no disposable authenticated browser fixture was available; responsive and source interaction behavior remain unverified rather than inferred from source.

Coordinator review inspected the initial-load and refresh callers, success/error branches, selection removal, the signed-source race, and the compatibility caller. Independent QA is pending under the required sequential single-writer execution. This tranche closes the two data-truthfulness defects only; it does not close D06's production-viewer, 320/360px, short-height, dark-mode, keyboard/touch, 200% zoom, selective Realtime/fallback freshness, pagination, or deployment acceptance.
