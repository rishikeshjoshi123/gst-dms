# D03-T02 — Enforce invite-bound verified-email signup

**Owner task / date:** current implementation coordinator, 2026-09-08

**Revision:** `9f7f49a`

**State:** review; independent QA, clean-browser acceptance, and deployed email delivery remain unverified.

Signup now fails closed unless the request carries the opaque, HttpOnly organisation-invitation intent created from an invitation link. Before Supabase Auth may create a user, the server hashes that nonce and calls a new non-disclosing database function that requires a live, unconsumed intent, a pending unexpired invitation, and the invitation's normalized email. The public RPC returns only `eligible` or `not_available`; it exposes no tenant or invitation identity. Signed-out invitation links now enter signup, existing users can still move to sign-in with the same intent, the auth callback returns verified users to invitation acceptance, and the signup page reports that email verification is pending instead of navigating to unrelated onboarding. The existing acceptance command remains authoritative for confirmed email and atomic membership creation.

Developer evidence passed against the disposable local Supabase stack and the Node 24 / Next 16.2.9 checkout: migration `00134` was applied explicitly; `invite_bound_signup.sql` passes normalized-email eligibility plus wrong-email, wrong-nonce, missing-nonce, and consumed-intent denial as `anon`; the three-test source contract proves both invitation checks precede `auth.signUp` and verifies the invitation-link → signup → verified callback → acceptance routing. Local generated types contain the new RPC without unrelated enum churn. The 134-version migration check and its unit suite, database type-refiner suite, local error-level schema lint, changed-file ESLint, TypeScript, whitespace validation, and both webpack and default Turbopack production builds pass.
