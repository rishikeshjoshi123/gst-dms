# D06-T06 — Add shared-viewer rotation and keyboard paging

**Owner task / date:** current implementation coordinator, 2026-09-08

**Base / implementation revision:** `8351e48` / `65df507`

**State:** review; local shared-component checks passed, while interactive browser, independent QA and deployment acceptance remain unverified.

The production `PdfViewer` shared by the Document Hub, canonical document route and legacy compatibility modal now rotates the current PDF clockwise in 90-degree steps. Rotation is passed to the PDF renderer, exposed through a visible labelled control with current-angle accessible text, and resets with zoom/fit/selection whenever the URL or source-locator page changes.

The bounded PDF page region is now keyboard focusable with a visible semantic focus ring and declared shortcuts. Left/Right and Page Up/Page Down move one page; Home/End move to the first/last page. Keyboard handling is scoped to that region and ignores interactive descendants, so page-number input, links, buttons and editable content retain their native behavior. Toolbar buttons and keyboard commands share the same clamped previous/next functions. Direct input, locator initialization and legacy jump events now normalize non-finite/fractional values and clamp against the loaded page count.

Developer evidence passed on Node 24 / Next 16.2.9: six focused shared-viewer and canonical-route tests cover responsive scroller ownership, fit-width controls, rotation/reset wiring, focus-scoped keyboard shortcuts, interactive-descendant exclusion, jump-event clamping and the canonical Hub consumers. TypeScript, changed-file ESLint, whitespace validation and the exact final webpack production build pass.

Coordinator review created a temporary public local viewer harness using the same shared component, but the Mac was locked and automatic unlock failed before the browser surface could be inspected. The temporary route was removed and the development server stopped before staging. Rotation geometry, keyboard interaction, 320/360 px wrapping, 200% zoom and screen-reader behavior therefore remain explicitly unverified in a browser. Independent QA and deployment acceptance remain open. D06 still retains continuous viewing, thumbnails/search, selective Realtime and downstream Workbench-consumer acceptance.
