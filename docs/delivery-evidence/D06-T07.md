# D06-T07 — Add bounded continuous PDF scrolling

**Owner task / date:** current implementation coordinator, 2026-09-08

**Base / implementation revision:** `160ab29` / `9582cb9`

**State:** review; local bounded-window and shared-consumer checks passed, while interactive browser, independent QA and deployment acceptance remain unverified.

The shared production `PdfViewer` now presents one continuous native scroll range instead of forcing one-page-at-a-time viewing. It keeps only the current page and two adjacent pages on either side mounted as PDF canvases; the remaining pages are lightweight geometry placeholders. A tested pure model clamps requested pages, enforces the five-canvas window, and preserves placeholder height across fit-width, manual zoom and 90-degree rotation.

An IntersectionObserver rooted in the viewer's one owned scroller identifies the dominant visible page and synchronizes the toolbar without snapping native scroll. Toolbar, keyboard, source-locator and legacy note-jump navigation use explicit page requests. Programmatic movement calls the viewer container's `scrollTo` rather than `scrollIntoView`, so it cannot accidentally scroll application chrome or another pane. Fit, zoom and rotation realign the current page after layout changes, while URL/source changes clear page geometry and restore the requested page safely.

Continuous rendering also repairs quotation attribution: text selection resolves the nearest rendered `data-pdf-page` element and persists that page with the quote. A neighboring rendered page can therefore no longer dispatch its text under whichever page happened to dominate the viewport. Observers, animation frames and source state retain explicit cleanup/reset ownership.

Developer evidence passed on Node 24 / Next 16.2.9: ten focused behavioral and source-contract tests cover safe page clamping, the maximum five-page render window, placeholder geometry in fit/zoom/rotation modes, continuous observer wiring, scroller-local direct navigation, selection-page attribution, responsive viewer controls and canonical consumers. TypeScript, changed-file ESLint, whitespace validation and the exact final webpack production build pass.

Interactive browser QA was not repeated because the Mac remained locked after the D06-T06 attempt. Actual long-PDF scroll stability, rapid scrollbar jumps, rotated mixed-size pages, quotation selection, 320/360 px, short-height, touch and 200% zoom behavior remain unverified. Independent QA and deployment acceptance remain open. D06 still retains in-document search, thumbnails, selective Realtime and downstream Workbench-consumer acceptance.
