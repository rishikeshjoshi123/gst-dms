# D06-T04 — Bound the canonical Intake queue

**Owner task / date:** current implementation coordinator, 2026-09-08

**Base / implementation revision:** `6dd0a05` / `e12c4fa`

**State:** review; local pagination, count and reconciliation checks passed, while authenticated data/browser acceptance, independent QA and deployment remain unverified.

The canonical Intake reader now defaults to a 50-row page, caps caller-controlled requests at 100 rows, applies a deterministic `created_at`/ID order, and obtains an exact server count. The navigation badge no longer derives its value from a partial page: it uses a separate head-only exact-count query with the same organisation and active-state fence. Invalid offsets, oversized limits and invalid selected IDs are normalized before they reach the database.

The Document Hub presents loaded versus total rows honestly and labels local filtering as a search of loaded documents. `Load more documents` requests another bounded page and remains available when the current loaded subset has no search match. Foreground reconciliation refreshes every page the user has loaded, fences overlapping queue requests by generation, preserves the last successful snapshot on any page failure, and removes selection only after an authoritative response no longer contains the selected Intake. A valid deep-linked Intake outside page one is retrieved through one additional organisation/state-scoped row query; arbitrary or malformed IDs cannot fail the base queue.
