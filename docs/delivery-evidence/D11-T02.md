# D11-T02 — URL-driven lazy Matter workspace shell

- **Outcome / owner / date:** D11-T02; current implementation task; 2026-09-08. This tranche replaces the live five-tab, eager Matter route with the canonical eight-section URL shell from the [Matter workspace plan](../plans/features/2026-08-25-matter-workspace-and-procedural-timeline.md#matter-workspace-route-and-state).
- **Base and tested code:** base `f53bc00`; implementation commit `4724ed2`. The commit contains only the scoped application, focused tests, and selectively staged Matter navigation design-system documentation/gallery hunks. Existing blocker, ledger, handoff, concept, portal, proxy, and unrelated design-system changes were preserved.
- **Developer evidence:** the route now resolves the exact authorised active/Trash Matter shell before section work, parses the canonical eight section IDs with Timeline default, preserves unrelated and repeated query state, and uses URL-authoritative document and inspector selection. Only the active section reader runs. Timeline and Files constrain exact tenant, matter, active state, deletion state, and proceeding/supporting class; the legacy-null proceeding adapter remains explicit. Inspector metadata receives one accepted ID only after membership/class validation. Timeline note preview uses an exact document-scoped reader and quotation locators without the full Notes/member-directory projection. Trash uses its retained exact snapshot only. Deadlines, Financials, and Activity are explicit unavailable states rather than invented projections.
- **Failure, authority, and UI contract:** Next 16.2 `unstable_catchError`/`unstable_retry` keeps Matter identity and navigation operable on section failure. Active lookup errors throw before Trash fallback instead of becoming false 404s. A server-derived capability fail-closes Viewer contribution controls; closed Matters suppress Timeline document/relationship mutations; Trash stays read-only. Desktop has the fixed opaque eight-item strip, while mobile has Timeline, Files, Case Brief, Notes, and an accessible More bottom sheet for the remaining four sections. Stable scroll ownership, safe-area padding, 44px targets, loading/error/empty states, and the design-system specimen/documentation ship with the implementation. The unreferenced legacy `MatterTabs` shell was removed.
- **Independent QA:** separate Sol/high read-only QA inspected the actual base-to-worktree diff, installed Next documentation, real callers, server readers, Trash projections, and query behavior. Its first pass found seven material defects: the wrong React boundary, missing authority gating, ignored inspector URL state, false-404 shell failures, dropped null-class proceedings, repeated-section disagreement, and broken legacy caller routing. After repair it found one transitive full Notes/member-directory read in Timeline. The coordinator added the narrow preview reader; final QA passed the repaired call graph and reconfirmed all prior findings.
- **Coordinator verification:** 51 focused Matter shell, URL/parser, inspector, Timeline, Brief, canonical-document, and Trash tests pass with `node --import tsx --test`; TypeScript, scoped clean-file lint, changed legacy-file lint with only its documented base-rule exclusions, and `git diff --check` pass. The final Next 16.2.9 webpack production build passes. The default Turbopack build produced no progress and was stopped before the verified webpack run. No migration or database write was required.
- **Browser / deployment gap:** the local development server reached ready state, but the Mac was locked and the browser controller could not unlock it. Authenticated direct-link/reload/Back/Forward, keyboard/focus/screen-reader behavior, 320px/tablet/desktop/200% zoom, light/dark/reduced-motion, and scrollbar/bottom-bar coverage remain unverified. No remote service, database, deployment, or production data changed.
- **Remaining work:** D11 remains `review`. Pagination and typed counts, measured 10/50/100/250 performance, the canonical chronology and relationship-backed graph, contextual upload intent, full capability projection, selective Realtime/freshness, and released Deadlines/Financials/Activity readers remain. The unavailable section states are truthful boundaries, not completion claims for those domains.
