# D06-T02 — Make the shared PDF viewer responsive by construction

**Owner task / date:** current implementation coordinator, 2026-09-08

**Base / implementation revision:** `05c3685` / `d8b8781`

**State:** review; focused responsive interaction passed, while authenticated live-consumer, broader viewer, independent QA and deployment acceptance remain unverified.

The production `PdfViewer` shared by the Document Hub, canonical document route, and legacy viewer modal now owns a stable toolbar outside one bounded page scroller. A `ResizeObserver` measures the actual pane and defaults the rendered PDF to fit width. The former fixed 600 px minimum height and raw white toolbar were removed, so a short or mobile pane no longer forces page-level overflow and dark mode uses semantic surfaces. The toolbar wraps, exposes a visible `Fit width` action, supports direct page entry, and gives previous/next/zoom controls effective 44 px touch targets. Manual zoom exits fit mode; changing the URL or source-locator page resets viewer state safely, and page count clamps the requested page after load.

Developer evidence passed on Node 24 / Next 16.2.9: thirteen focused viewer and canonical-route tests, including the bracketed route suite run directly because the test glob reports zero files; TypeScript, changed-file ESLint, whitespace validation, and the webpack production build pass. Two stale route assertions left by the earlier signed-result union narrowing were corrected to the already-live `signedDocumentUrl` contract; no production route behavior changed in that test repair.

Coordinator browser review used a temporary public local composition with a public Mozilla PDF, then restored that file byte-for-byte before staging. At a true 320 × 568 viewport, document/body scroll width equalled the 320 px client width, the PDF fit the 304 px content pane, the toolbar wrapped into two compact rows, all five buttons measured 44 px high or more, dark presentation remained coherent, next-page navigation changed page 1 to page 2, and browser logs contained no warnings/errors. The temporary composition is not committed.

Independent QA remains pending under sequential single-writer execution. This tranche does not close D06: authenticated Hub/canonical/Trash consumers, 360 px and short-height variants, 200% browser zoom, touch/selection behavior, continuous-page/rotation/search features, selective Realtime/fallback freshness, pagination, and deployment acceptance remain unverified.
