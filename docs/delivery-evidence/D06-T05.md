# D06-T05 — Bound Intake placement destinations

**Owner task / date:** current implementation coordinator, 2026-09-08

**Base / implementation revision:** `dbd14f2` / `0c33586`

**State:** review; local bounded-search and consumer checks passed, while authenticated database/browser acceptance, independent QA and deployment remain unverified.

The canonical `/documents` loader no longer calls the unbounded organisation-wide `getMatters()` reader. It now requests a bounded destination projection through the signed-in Supabase client and active organisation fence. Empty search returns at most 20 recent active matters. User search runs independently bounded title, matter-code, financial-year and client-name queries, escapes SQL `LIKE` wildcard characters, deduplicates the result and returns at most 20 matches. Explicit context IDs are validated, deduplicated and capped at 60 before a separate active-matter lookup.

That context lookup preserves labels for the first bounded Intake page, a valid URL destination and an intended or currently selected matter without making every active matter a page dependency. Later Intake pages hydrate only their bounded destination IDs. The placement UI replaces the native all-matter select with a debounced, labelled server-search list, 44 px options, visible selected state, loading/empty/error copy and honest result-limit guidance. Request generations fence late results. A selected destination is cleared only when an authoritative result says it is no longer accessible.

Coordinator review found and repaired a dynamic-state race: refreshing search results could initially reset a user's manually chosen alternative to the Intake's intended matter. Placement initialization is now fenced by selected Intake identity, so late option hydration cannot overwrite an active choice. Search and queue lookup failures preserve the last usable options and do not make the queue itself unavailable.

Developer evidence passed on Node 24 / Next 16.2.9: 14 focused routing, queue, pagination and destination tests cover bounded inputs, wildcard escaping, required-context preservation, exact queue counts, source/queue generation fences, explicit empty/error behavior, removal of the unbounded Hub caller, and placement-selection fencing. TypeScript, changed-file ESLint, whitespace validation and the webpack production build pass.

No disposable signed-in fixture was available, so live PostgREST matching across representative matter/client names, RLS behavior, keyboard/screen-reader interaction and narrow-browser presentation remain unverified. Independent QA, remote performance and deployment acceptance remain open. D06 still retains selective Realtime, remaining shared-viewer features and downstream Workbench-consumer acceptance.
