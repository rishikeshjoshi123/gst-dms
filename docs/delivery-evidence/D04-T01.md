# D04-T01 — Cut global and matter uploads over to direct private Storage

**Owner task / date:** current implementation coordinator, 2026-09-08

**Base / implementation revision:** `2976e09` / `78a4884`

**State:** review; local source/build acceptance passed, while authenticated browser, adversarial lifecycle, independent QA, deployment and release acceptance remain unverified.

The three live upload callers—the dashboard quick upload, global Inbox modal, and matter dropzone—now share one browser transport. A server action first invokes the canonical `reserve_document_upload` command, then creates a short-lived signed upload token for the exact private `documents/orgs/{org}/assets/{asset}/original.pdf` key. `tus-js-client` sends the PDF directly to the Storage resumable endpoint in 6 MiB chunks with retry delays, creation data, visible per-file progress, and session-scoped URL persistence. It does not set upsert. A same-tab marker resumes finalization without replaying an already-complete immutable transfer.

Finalization accepts only the upload-session and idempotency UUIDs. It re-authenticates the actor, binds the session to that actor and active organisation, re-derives the asset locator from lifecycle rows, downloads the stored object through the service boundary, and uses the existing server-observed signature, size and SHA-256 checks before `complete_document_upload`. Duplicate and terminal cleanup continue to require durable lifecycle ownership. The legacy file-bearing Server Actions and their Inbox/matter wrappers were removed. The now-unneeded 27 MB Next proxy and Server Action buffers were removed as well.

Developer evidence passed on Node 24 / Next 16.2.9: nine focused lifecycle/transport tests, the direct-transfer Next configuration test, changed-file ESLint, TypeScript, lockfile dry-run validation, whitespace validation, and the webpack production build. The full ESLint command still reports the recorded B02 repository baseline; no changed-file diagnostic remains. The local Inbox route redirected to login and no disposable authenticated browser fixture was available, so no file was transmitted and browser behavior is not claimed. No database schema, remote environment, or production data changed.

Coordinator review inspected all three callers, the signed-token boundary, immutable metadata, resumption scope, finalization authority, and absence of a browser-file parameter in Server Actions. Independent QA is pending because the user required one sequential active writer. This tranche commits the live transport foundation but does not close D04: authenticated 25 MiB, interrupted/resumed transfer, expired authorization, cancel/finalize race, duplicate/retry idempotency, responsive UI, remote Storage, and deployment acceptance still require execution at their applicable gates.
