# D06-T08 — Add bounded cancellable PDF text search

**Owner task / date:** current implementation coordinator, 2026-09-08

**Base / implementation revision:** `cdb9347` / `b5fa4bb`

**State:** review; local bounded-search and shared-consumer checks passed, while interactive browser, independent QA and deployment acceptance remain unverified.

The shared production `PdfViewer` now searches selectable PDF text in explicit batches of at most 25 pages. The interface reports exact completed coverage and matching-page counts, distinguishes partial from complete coverage, and requires another user action before scanning the next batch. A normalized query is bounded to 100 characters. Results represent matching pages rather than every occurrence, and previous/next controls navigate through those pages using the viewer's scroller-local page request path.

Search work is fenced by both a generation token and the loaded PDF proxy identity. Changing the query, cancelling, changing the source locator or loading another document invalidates stale asynchronous work. A failed page extraction preserves only fully completed coverage and reports where scanning stopped; cancelled partial batches do not overstate coverage. URL changes clear document-owned state, while initial-page-only changes retain the loaded proxy and page registry so source-locator navigation does not strand search until a redundant reload.

Only pages already identified as matches receive text-layer highlighting. Highlight rendering escapes untrusted PDF text and the query is regular-expression escaped before matching. The search input has an instance-safe accessible label, controls retain 44-pixel targets, status is announced politely, and the completed state does not advertise a zero-page follow-up action.

Developer evidence passed: thirteen focused behavioral and source-contract tests cover 25-page batching, completed coverage, bounded query normalization, safe highlighting, cancellation/document fencing, match navigation, existing responsive controls, rotation, keyboard navigation, the five-canvas continuous window, placeholder geometry, selection attribution and canonical consumers. TypeScript, changed-file ESLint, whitespace validation and the exact webpack production build pass. The successful build emitted the existing Supabase Node-version deprecation warning but no build failure.

This tranche searches text exposed by PDF.js from the PDF itself. It does not search server-side OCR artifacts and does not claim OCR coverage. Interactive browser QA was unavailable because the Mac remains locked; actual long-document latency, cancellation timing, keyboard/screen-reader flow, 320/360 px wrapping, short-height layout, touch and 200% zoom behavior remain unverified. Independent QA and deployment acceptance remain open. D06 still retains thumbnails, OCR-integrated search, selective Realtime and downstream Workbench-consumer acceptance.
