# D15-T01 — secure Team member directory

- **Outcome / owner / date:** D15-T01; current implementation task; 2026-09-08. This tranche delivers the approved read-only Team Members workspace and basic inspector without claiming that invitations, departure, administrative removal, grants, or work-impact workflows are live.
- **Base and implementation:** base/evidence parent `cef0fde`; implementation commit `b3837d5`. The commit contains migration `00139`, its rollback acceptance fixture and generated RPC types, the typed server reader, `/team` route and responsive workspace, navigation, Settings member-list removal, deletion of the unused unsafe legacy `removeMember` action, the shared display-name-only Avatar fallback, and focused tests. Existing approval, ledger/handoff-top, design-system, concept, portal, platform-plan, proxy, decision-history, and review-document changes were preserved.
- **Directory authority:** `get_team_directory` derives the caller and tenant only from `auth.uid()` and requires exactly one active `team.view` context. Zero or multiple eligible contexts return an explicit unavailable sentinel. Ordinary members receive active teammates and only their own confirmed email; Owner/Admin may also receive suspended members and authorised emails. Removed and foreign memberships are omitted, and `anon`/`service_role` receive no execute grant.
- **Search and pagination:** role/state inputs are allowlisted, query/limit/offset are bounded, `%`, `_`, and backslash are literal search characters, and filtering considers only visible display name and caller-authorised email. The RPC distinguishes unavailable from a legitimate empty result and returns an authoritative total plus canonical page offset even when the requested page is out of range.
- **Live workflow:** `/team` is first-class desktop/mobile navigation. Desktop renders the exact Person/Role/Status/Joined table with 48px rows and a wide-screen 60/40 inspector split; mobile/tablet use list-to-detail navigation. Owner is a separate overlay on the actual role. Selection, Back/Close, post-render focus return, fixed-width badges, explicit missing fields, bounded capability summaries, loading/error/empty/no-match states, semantic tokens, and 44px mobile controls follow the approved contract. Settings retains invitation behavior but no longer presents the Team member directory.
- **Independent QA:** a separate Sol/high reviewer inspected the complete working-tree diff and real callers. Its first pass found fail-open multi-context selection, ambiguous empty/error outcomes, pagination/search, ownership, responsive selection, density/loading, and touch-target defects. After bounded repairs it found narrow-layout filter overflow, loading-shape drift, and an email-derived Avatar caller. The final pass returned PASS with no P0–P3 findings and reconfirmed the security, data, UI, and expanded SQL-fixture contracts.
- **Coordinator verification:** eight focused Team/reader/navigation/initials tests, three migration-check tests, and four generated-type-refinement tests pass under Node 24. TypeScript, scoped ESLint, the 139-version migration numbering check, `git diff --check`, and the Next 16.2.9 webpack production build pass. The build includes dynamic `/team` and emits only the existing Supabase Node 20 deprecation warning where applicable.
- **Gaps / remaining work:** the rollback SQL fixture was statically reviewed but not executed because no disposable Supabase database was confirmed. The Mac remained locked, so authenticated ordinary/Admin projections, actual 320px/200% zoom, keyboard focus return, dark mode, and live scroll ownership were not exercised in a browser. No database, remote service, deployment, or release state changed.
