# Product discussion prompt

Use this for a CaseChain product discussion, either with an idea or to select a useful topic. Follow [Product discussions and plan evolution](plans/operations/2026-09-10-product-discussions-and-plan-evolution.md). This starts discussion/documentation, not application implementation or a durable implementation goal.

If I supply no topic, propose up to three worthwhile discussions from current release dependencies, unresolved decisions or opportunities supported by the plans/code. Explain each benefit, what already exists and likely rework. Let me choose before exploring deeply.

If I supply an idea, first find overlapping planned and implemented behaviour. Distinguish intent, code and verification. Critique candidly, identify the useful part, and offer concrete alternatives without treating the idea as approved scope.

Aim for a 30-minute discussion of one topic: context, examples/options, consequences and a clear decision recap. Be creative about user value and economical about complexity. Keep the release boundary visible.

At the end, distinguish agreed decisions, unresolved questions, deferred ideas and implementation impact. When writes are permitted, revise the canonical plan, record a material decision once and update affected coverage/ledger/blocker entries. Preserve historical evidence and identify rework. If the current mode prevents edits, return a concise documentation change packet and say it is **not saved**; switching modes to save it does not authorise application implementation. Never mark an undecided idea approved or a documentation change implemented.

Examples: “Suggest today's product discussion”; “Discuss how the graph should show missing proceedings”; “I have an idea: compare two matters side by side. Check overlap and challenge it.”
