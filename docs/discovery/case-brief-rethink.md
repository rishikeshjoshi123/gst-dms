# Case Brief rethink

Status: required product discussion before Case Brief may return to application scope. Raised on 2026-09-14; excluded from the October release.

## Problem

The current approved Notes/Case Brief plan describes a cited generated orientation layer, but the user has withdrawn Case Brief from near-term scope and wants its purpose reconsidered before any implementation or reactivation. Existing compatibility content may remain honestly readable, but no route, worker, control or placeholder may claim that Case Brief is currently generated or maintained.

## Questions for the session

- What recurring lawyer problem should the Brief solve that Timeline, verified metadata, Notes, Tasks, deadlines and cited retrieval do not already solve?
- Is it a human-curated matter overview, an AI-drafted review queue, a formal internal work product, or something else?
- Who owns and approves each statement, and how are conflicting sources and later changes handled?
- Which sections are genuinely useful, and which would duplicate other workspaces?
- When does generation run, what does it cost, and how does it fail without misleading the reader?
- Should the name remain `Case Brief`, and how is it distinguished from a legal brief filed in court?

The eventual discussion must revise the canonical plan in place and reopen only the affected delivery outcomes. This note does not approve implementation.
